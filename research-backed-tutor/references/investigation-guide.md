# 知识调查与关系网络

在建立知识地图、寻找缺口和组织讲解时使用。将白月光学习法的“追线索”结构转化为可核验的知识调查，不采用其人物窥探叙事，不把示例当作学科事实。

## 十二个调查入口

| 调查入口 | 学习中的对应物 | 必须回答 |
| --- | --- | --- |
| 账号／目标 | 当前知识对象和边界 | 它是谁？准确定义是什么？属于什么，不属于什么？ |
| 信息源 | 教材、原始研究、课程、项目 | 哪个结论来自哪里？实际读到哪一级？ |
| 关注列表 | 邻近与共现概念 | 常和谁一起出现？仅相关，还是存在依赖？ |
| 点赞记录 | 高频但需核实的特征 | 哪些关键词代表它？为何重要？高频是否只是流行表述？ |
| 收藏夹 | 必留定义、条件、机制与例子 | 删除哪项会使解释或应用出错？最小核心与完整细节分别是什么？ |
| 历史记录 | 理解所需的前置知识 | 哪项未教会就无法推导下一步？按依赖顺序补齐。 |
| 共同好友 | 跨学科连接与使用者 | 谁使用它？使用目的、输入输出和条件是什么？ |
| 关系网 | 节点及带类型的边 | 谁依赖谁、怎样连接、依据何在、何时失效？ |
| 时间线 | 实际发展史与解决问题的演变 | 什么问题促成它？史实来源是什么？教学顺序另列。 |
| 重复信息 | 同义重述或可推导结论 | 能否在明确前提下证明等价或导出？重复内容有无独立证据价值？ |
| 新信息／新线索 | 新概念、条件、证据、反例与争议 | 它增加了哪种理解？已有内容为何推不出它？ |
| 下一条线索 | 最值得继续学习的分支 | 它解决哪项剩余问题？是必需缺口还是可选扩展？ |

同时贯穿三个问题：**它为何存在、没有它会怎样、哪个机制构成其本质？** 用具体任务或反例回答。删去一个概念后导致的失败只能在模型和条件内说明，不夸张为“没有它世界无法运行”。

## 节点卡与边表

每个节点有稳定 ID，记录：名称／别名、范围层级、日常解释、准确定义、目的、本质机制、符号与单位、前置知识、条件、推导位置、正例与反例、易混项、应用、细节、来源及访问状态。字段可说明不适用，不能用空白掩盖缺口。

“本质”要落到可区分该概念的结构、机制或不变量，再用例子检验；不能用一句漂亮口号代替定义和推导。

边表格式：

| 起点 ID | 关系类型 | 终点 ID | 方向与条件 | 解释／推导 | 证据 | 对应检查 |
| --- | --- | --- | --- | --- | --- | --- |

按实际含义选择关系：`前置`、`定义组成`、`条件下推出`、`特例／推广`、`因果机制`、`应用于`、`对比／不等价`、`历史影响`、`普通关联`。不要把所有箭头都画成依赖。双向关系需要分别核查，不能因为 A 推出 B 就画成等价。

画两类视图：先给核心概览，再给分支细节；图太大时分图并以节点 ID 交叉引用，保留完整节点和边表。Mermaid 可用于紧凑图示，也要附无需软件的手绘步骤：中心对象 → 前置 → 定义／机制 → 条件／推导 → 易混项／反例 → 应用／项目 → 细节分支。

## 覆盖和去重

建立 `节点／细节 → 来源 → 讲解位置 → 初学者输出 → 检查结果` 的矩阵。所有当前范围内核心与必需细节都要有对应项。列出可选扩展和未知项；凡影响核心正确性的缺口必须升级为必需项。

只有已给出等价变形、明确的推导，或确认同义的内容才能按“重复”合并。合并表达时保留出处；独立来源提供交叉核验价值，即使结论一致也不是无价值重复。新增前提、反例、不同视角或争议不能被删掉。

上游调查例子中“关注某人且给其点赞”不足以推出“双方互关”。这说明线索之间的关系需要证明：共现、主观猜测、概率证据和必然推论是不同关系。一般意义的“不能推出”也不能直接替代数学中的“线性无关”。

同样，学习路线“函数 → 极限 → 导数 → 积分”不自动证明逻辑必需关系或真实历史顺序；“有终止条件”也不自动证明程序一定到达终止条件。将这些区别作为关系图和初学者输出的检查点。

## 调查档案的输出

使用准确学习术语为主，调查昵称可作为辅助。给出目标、来源、核心身份、动机与目的、前置、核心收藏、关联与依赖、带条件的关系图、发展过程、可推导内容、新增线索和下一步。调查档案连接到完整讲解和项目验证，不能代替它们。
