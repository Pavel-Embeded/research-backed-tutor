# 完全零基础与逐句易懂检查

本文件用于每次实质教学的编写、修订和最终复检。目标是让对该领域一无所知的人尽可能省力地理解每一句，并能根据讲解自己输出。不能用整段大致通顺、抽查几句或模型自报满意代替逐句检查。

## 起点：不预设任何领域知识

先写清初始允许使用的基础：用户使用的日常语言，以及当前例子确实需要的日常经验。日常经验也可能不熟悉；必要时用一句具体说明补齐。不能默认用户懂专业常识、英文缩写、数学记号、代码语法、软件操作或专业图表。不要把用户按年龄或智力贴标签，使用尊重、自然的语言。

维护按阅读顺序排列的“已教知识清单”。一个知识点只有在定义、需要的前提和解释已经出现在此前内容中时，才可被后面的句子直接使用。只列过名称、在后文才解释、存在于答案页或模型记忆里，都不算此时已经教会。第一次出现专业名称时，可以在同一句用日常语言立即解释；若解释仍需新词，先拆开并教这些词。

每轮从同一初始基础重新开始阅读最终版本，并随着阅读累积已教内容。不能因上轮已经看过完整答案，就默认这一轮初学者提前知道答案。用户明确希望沿用的基础可作为声明的起点；不得自行推定。

## 写出理解成本低的句子

- **先具体再命名**：先说明一个可想象的问题、动作或变化，再给必要名称和准确含义。解释不能绕回同一个陌生词。熟悉例子如果会引入新知识，应先补齐例子的背景。
- **一个主要意思一小步**：一句尽量只做一个主要动作。多个条件、结论或转折挤在一起时拆开，并说清连接关系。没有固定字数标准；短句也可能很难懂。
- **主体与指代清楚**：写明哪个对象发生什么，少用含糊的“它”“这”“上述”。相邻对象容易混淆时直接重复名称，避免让读者猜。
- **把推理的桥补上**：前提在哪里、现在做了什么、为什么能这样做、由此得到什么，都要能在讲解中找到。“显然”“易得”“自然就”“只需”不能替代必要步骤。
- **保留准确条件**：通俗表达之后保留精确定义、符号和限制，并说明它们怎样对应。不能为顺口而把“有时”改成“总是”，把类比写成事实，或删掉关键例外。
- **不增加无用负担**：优先使用必要且一致的词；不为显得专业堆术语。用小例子支撑难点，不给每句机械添加一大段故事。先给当前需要的内容，再逐步展开范围内的细节和关系。

## 检查范围：每一句都包括

建立最终用户可见内容的清单，并给每个句子分配可追踪的编号。正文、列表、练习、答案、来源状态、项目说明和验收摘要都在范围内。段落有三句话就检查三句，不能只给整段一个“通过”。

没有完整句子的内容也不能漏：标题、表头与表格单元格、图中节点与关系标签、图注、公式、代码、注释、运行命令、输入输出示例等，作为有编号的表达单元逐项检查。长单元按含义拆开，不能合并成一个大单元掩盖漏检。引用原文、文件名、URL 和固定命令应保持原样，在旁边解释陌生含义与使用方法；不用改坏原内容来降低难度。

表达单元以实际含义为准。纯排版的空行、Markdown 表格分隔横线或对齐标记不单列为知识项。影响理解的符号、关系标签和代码语法仍须解释，不能以“只是排版”为由跳过。

公式先解释每个记号的含义与取值，再说明怎样读、做了什么变化以及为什么成立。图先教节点、连线、方向和标签怎样读，再从小图扩展到完整图。代码和命令先教必要语法与操作，指出在哪里输入、需要什么文件、运行后应看到什么。不能靠正文通俗就默认用户会读另一种表达。

## 每一句的检查动作与记录

初学者在阅读到当前句子时，只能使用该句之前的已教内容与声明的日常基础。对每一句执行以下检查，保持按句的覆盖，而不是每句都机械问同样的问题：

1. **词与对象**：每个词、符号和对象具体指什么？有陌生项就提出具体问题。
2. **意思与连接**：这句话在说哪一件事？它与前一句怎样连接？所用前提是否已经教过？检查指代、跳步、条件和隐含技能。
3. **自己说出来**：用自己的通俗表述说明该句意思，不能照抄原句。事实句或指令句说明事实或实际动作；标题和标签说明其用途；公式与代码说明操作和结果。必要时用微型例子或操作轨迹核验，不能为凑例子假造历史事实。
4. **核验并改讲解**：核验者检查复述是否保持条件、因果与准确性，是否偷用未教知识。有疑问、错误或只能重复陌生词，便修订该句及所需前置，再检查新版本。

记录是可复查的简短产物，不是私有思维链：

| 字段 | 要保留的事实 |
| --- | --- |
| 版本与句／单元编号 | 能定位到最终文本；保留拆句、新增和删除后的对应关系 |
| 原句／表达单元 | 当前检查的实际内容，不能用段落标题替代 |
| 依赖 | 需要的词、符号、前提或技能；对应此前已教编号或声明的日常基础 |
| 初学者产物 | 简短的自己的复述、具体问题，或适用的操作结果 |
| 核验与修订 | 具体障碍、正确性检查和讲解修改；无问题也保留复述证据 |
| 复检结果 | 新版本通过、仍有问题或未检查；记录真实结果 |

不能预填“通过”，不能用自动分句脚本、术语数量或可读性评分当作理解证据。脚本可帮助检查编号是否遗漏，但不能替代语义核验。记录可以保存在当前工作文件，或形成当前任务中可复查的检查产物；没有实际完成的记录就不能宣称逐句检查完成。

## 修改后从哪里重新检查

补一句解释会增加检查对象；换词、移动顺序或修改条件，会影响后文依赖。先检查新增／改写的每一句，再重查所有受影响的后文、图表、练习答案和项目步骤。重排后更新编号和依赖，不保留失效的“通过”标记。

最终版本确定后，从零顺序复检全部句子和表达单元。任何用户可见内容在此后新增或修改，包括最后写的摘要和答案，都要检查并同步更新最终版本。不能先宣布逐句通过，再添加未检查的一页说明。

## 逐句通过的必要条件

最终清单中的每一句和表达单元都有实际检查记录，覆盖率为已检查项数／总项数，必须达到 100%。全部依赖能追溯到已教内容或声明的基础；每项均有保持原意与条件的初学者输出；所有已发现的陌生词、隐含前提、歧义、跳步和错误复述均已修订并复检。漏检项或未解决项只要存在，就不能标记这一门槛通过。

按 [mastery-loop.md](mastery-loop.md) 继续检查知识网络、迁移与独立项目。连续两轮不同挑战都要覆盖同一最终版本的每一句，每轮更换提问角度、复述方式或适用的小检查；不能复制上一轮记录。最终句子有变化就重新开始稳定轮数。逐句顺畅不能代替整体理解和实际能力检验。

## 交给用户的形式

给用户修订后的自然讲解、分层关系图和能照着做的步骤，不在每句话后插入审查表或角色对话。摘要只需说明检查版本、句子／单元总数、实际覆盖、未解决数和少量代表性纠正；详细记录供复查。需要用户检验时，在自然的知识节点安排小任务，并给答案和补课入口。

“模拟初学者逐句检查通过”只描述实际执行的检查。不能据此说已经证明真实用户每一句都懂；真实用户指出任何一句不懂时，立即定位、补讲并重查依赖。若受到真实资源限制，保留未检查项与下一步，输出清楚标记的阶段成果，不把抽查伪装成完整逐句检查。
